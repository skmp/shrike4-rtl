## What is already established (re-verified this session, do not re-litigate)

The internal sine value on the 2^-26 grid is

    V(node n, offset t) = C0_n  +  s*T1  -  T2  -  s*T3          s = -1 for nodes 17..31 (cos sign flips)

with the FIPR Booth array `arr(rec, mul)` and `sm(P,u) = P>=0 ? P>>u : -((~P)>>u)`, K = 2^19,
dx = t<<13, and (all in `base2.h`, coefficient rules derived, nothing fitted):

    T1 = sm(arr(C1f_n, dx) + K, 23 - e1_n)                 C1f = RN23(cos(n pi/32) * pi/2 * 2^23) field
    A3 = ((arr(t*t<<3, dx) + K) >> 20) >> 3                cubic's t^3 latch
    T3 = sm(arr(c3_n<<5, A3) + K, 26)                      c3 = RN(cos(n pi/32) * 2646), 12 bit
    T2 = sm(arr(J, S_n) + K, u2_n)                         S = RN(sin * 2^(23+k)) in [2^22,2^23), u2 = 30+k
    C0_n = the 26-bit table value (b2.cpp fits it inside the t=0 window; t=0 forces V = C0)

Facts measured this session:

* The **fundamental domain is nodes 0..31** (32768 samples).  cos(a) == sin(a+0x4000) bit-exactly, so the
  cosine half of the dump carries NO extra information; sin(a+0x8000) == -sin(a); but
  sin(0x8000-a) != sin(a) in 6692 of 65536 cases, so nodes 17..31 ARE independent data.
* The hardware's dx^2 latch is EXACT: floor((arr(dx,dx) + 2^19) / 2^26) == t*t for all 1024 t.
  Without the 2^19 constant it fails for 896 of them (arr(dx,dx) is short by 2^17 or 2^18), so K = 2^19 is
  what makes the square exact.  A dx^2-first square path is therefore SYMMETRIC in t.
* Current model score: **148 window violations over nodes 0..31**; nodes 0, 1, 2, 16 exact.
* **The entire residual is the square path's latch J.**  With a free integer J(t) chosen per t (one value
  shared by all 31 node instances) the model drops to **2 violations** (only t = +-17 survive).
  Control: a free per-t offset in the cubic latch A3 gives 147 (i.e. explains nothing), so the
  attribution to the square latch is unambiguous.
* If J is forced EVEN in t the floor is 70 violations, so a genuine sign asymmetry is required,
  but the current chain's asymmetry is the wrong one (148 > 70).
* 45 of 510 |t| have DISJOINT allowed intervals for J(+t) and J(-t); the required asymmetry
  D(|t|) = J(-t)-J(t) is NOT monotone in t: D = 0 exactly at |t| = 40 and 376, but D in [6,7] at
  |t| = 342 and D >= 1 at 45 other |t|.  So D is bit-pattern dependent, not of the form a*t.
* The current chain  I1 = (arr(KC,dx)+K)>>23 ; J = (arr(I1,dx)+K)>>20  with KC = 0x4EF145 puts J inside
  the allowed interval for 926 of 1022 feasible t (934 with the second rounding constant dropped).

## The two open items

1. **Find the datapath rule that produces J(t).**  It is a single 24-bit latch value per t, roughly
   2*2pi^2*t^2, with a non-monotone sign asymmetry.  Whatever produces it must also be buildable from
   the operands the hardware has in that step: dx = t<<13 (signed 24-bit), the exact t^2 latch, the
   constant 2pi^2, and the previous multiplier outputs (feedback into the input latches).
2. **t = +-17.**  No integer J satisfies all nodes there: table 5 (both sides) forces J <= 11404 while
   table 8's flipped side (node 24) forces J >= 11405 (ideal J = 11407.19).  One of S_8, u2_8, C0_8,
   the final product's rounding, or the flipped-side sign convention must be off by one hair.
