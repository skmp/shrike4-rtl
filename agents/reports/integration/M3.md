## 2. The grafted probes (`tb/bm/graft`, new)

**The finding.** Each bare-metal port recompiles a console probe against a KOS stand-in, which moves its code and its
data. With IDEAL_MEM = 1 that does not matter. With the real caches it decides the result.
- soc-design `c1g`: the port puts `c1_ts`, the handler's per-iteration record array, on the operand-cache indices of
  `c1_asm`'s literal pools. The loop paid +0.1 Icyc per iteration that the console never paid.
- `ci4` / `c1` "max" columns: a harness–loop IC conflict made every run miss twice, and one run's miss met a refresh.

**The mechanism.**
- `tb/bm/graft/graft.py` takes the console build's own ELF (`tools/hw/<suite>/<prog>.elf`): KOS and the probe, byte
  for byte, at the console's addresses.
- It redirects a few KOS entry points to a small runtime, with a `mov.l @(disp,PC),r0 ; jmp @r0 ; nop` stub over each
  function's first bytes:
  - `start`;
  - the printf family;
  - the allocators;
  - `abort` / `exit`;
  - KOS's time getters (the ports' convention of 2,000 Icyc per ms).
- The runtime runs from **P2**, so the harness takes no cache line.
- `crt0.S` recreates KOS's start-up state:
  - stack 0x8CFFFF94, which is `arch_stack_16m` less `arch_main`'s 108-byte frame;
  - FPSCR 0x40000;
  - PMCR1 0xC023;
  - IMASK 0 before main.
- `--irq` repeats KOS's `irq_init` (inlined by LTO into `arch_main`) through KOS's own functions and tables. Probes
  that install handlers then run through KOS's dispatch.
- The output is an ELF with two PT_LOAD segments, which `soc_tb` and `Sh4Sys` load as is.

**The evidence it works.**
- grafted `ci4` on `rm`: `ram_fd` 14.996 (max 14.996) and `ram_fdm` 14.992, the console's values to the last digit
  (the port gave 15.000 / 15.082).
- soc-design `c1d` .. `c1h`: pass at level cache. On the port, `c1d` / `c1e` / `c1f` / `c1g` / `c1h` all failed.

**Which probes can be grafted.** Only a probe whose kept ELF is the image the console ran, judged by timestamps. The
graftable ones are:
- soc-design (all);
- core-exc c1i / c1k;
- core-integration ci .. ci4;
- excint3, ubcbrk, scif_probe, cachetest3.

These keep their ports:
- excint, because `excint_asm.S` changed after run 1;
- cachetest / cachetest2, because `kern.S` changed after runs 1 and 2;
- bsc-memmap (below);
- the DMAC ports, which are rewrites of the bare-metal parts;
- mmubm, which has its own result-block harness.

**bsc-memmap at the run's layout** (`tb/bm/bsc-memmap/bm.ld`, `bm_bscmm.ld`, `bm_bscmm2.ld`, `layout.py`, new).
- The kept `bscmm.elf` is **not** the run's image. The log was written at 04:05, the ELF linked at 04:10, and in
  between `gen_tests.py` added run 2's kernels (0xF40 bytes).
- The port therefore links the probe's code and kernels at the console's addresses, KOS's
  `irq_disable` / `irq_restore` bytes and the kernel table 0xF40 below the ELF's, and memalign returns the console's
  buffers.
- `layout.py` checks all 189 symbols against the console's ELF with that shift.
- **Validation:** the console's `oc_hit c_rd` K = 24 anomaly (92, "IC conflicts") reappears exactly. At the run's
  address, `irq_disable` sits on IC entries 0xFF / 0x00, which are `t_c_rd_24`'s lines. Every `ram` read / write row
  of bscmm is now exact.

## 3. RTL fixes (cross-owner files; each has a regression test and a planted bug)

1. **`v1_ocache.sv` (WI-CACHE), event 0x22.**
   - It now counts a line read's tenure at the BSC: from the accept to the critical word's delivery. That is 14 at
     either Bclk phase **[HW 14.25]**; the old claim-to-rd_v count gave 13 / 14.
   - Test: `g_events`, both phases. Mutant `ocfill_ev_claim`.
2. **`v1_ocache.sv`, the same-entry fill queue.**
   - A load / PREF fill's entry may be claimed by the next miss (`fq`). The first fill then completes without V, and
     `lm_f` stops serving it once `fq` owns the entry.
   - ci4 `miss_em` 28 **[HW 28.137]**; waiting gave 32.
   - Tests: the same-entry miss has latency 15; the replaced line misses; PREF A / PREF B / load A misses; a
     store-allocated fill keeps its entry.
   - Mutants: `fq_no_same_entry`, `fq_same_entry_store`, `fq_old_line_hits`, `fq_old_line_valid`.
3. **`v1_sq.sv`, the release register.**
   - A queue is released one Bcyc after its burst's `done`: `rls`, clocked by a new `ce` port that `v1_soc` wires.
   - PREF ; store 18.23 and SQ0 only 22.23 **[HW]**.
   - Test: the SQ store waits until `done` + 3. Mutant `sq_no_rls`.
4. **`v1_soc_pkg.sv` `ireq_t.spec` + `v1_fetch.sv` + `v1_icache.sv` (WI-0 / WI-CORE-B / WI-CACHE).**
   - `spec` marks the request of a kill cycle or a new stream's redirect cycle, whose word the fetch drops. It is
     held for a re-presented request (`rq_spec`).
   - The IC starts no fill for it and answers a cacheable one at once.
   - core-exc c1i `ld_n trap`: RTE's discarded word is the next line, which shares the loop's IC entry. The fill
     evicted the loop line every iteration: 92 against the console's 35. **Now 35; c1i passes.**
   - Answering the request at once fixes a **deadlock** that mmubm on `rmx` found. There, a spec request behind an
     ITLB refill is waited for by the redirect.
   - Tests (cache tb): an abandoned request starts no fill and counts no 0x08 / 0x24; one behind a 5-cycle stall is
     answered without a fill.
   - Mutants: `ic_spec_fills`, `ic_spec_unanswered`.
   - Lint waivers for the unused bit in `v1_mmu.sv` and `v1_ideal_mem.sv`.
   - `tb/v1_fetchx_tb.{sv,cpp}` skip the data check for a spec word (`if_spec` output).
5. **`v1_bsc_arb.sv`, `v1_bsc.sv`, `v1_bsc_pkg.sv`, `v1_biu.sv` (WI-BSC), write-after-line.**
   - A CPU write of another line after a CPU SDRAM line read is accepted at the line's critical beat. The record
     carries `sd_ln` and `la`; the front end issues it (`wovl`).
   - `v1_biu` routes the write-data pulls to the oldest write owner.
   - A refresh / SDMR / PALL clears the state.
   - The dirty-victim chains now take 42 **[HW 41.89]**, and the victim in another bank 24 **[HW 24]**.
   - Mutants: no write-after-line; the same line; a refresh keeps the state (caught by unit `order`).
6. **`v1_bsc_arb.sv`, read after read.**
   - Accepted one Bcyc after the earlier read's critical beat: the PREF stream takes 14, and stldo the expected 56.
   - Mutant: read-after-read at the critical beat.
   - The old "no read overlap" mutant is now equivalent, because the bus rule gives the same Bcyc. It was removed
     with a comment.
7. **`v1_dmac_xfer.sv` (WI-DMAC) + `v1_bsc_arb.sv` + `v1_bsc_sdram.sv`, the DMAC pair.**
   - `early_w`: the write is presented right after the read's accept.
   - `dwovl_ok`: the write is accepted at the read's critical beat.
   - `lk_st` 3: the pair holds the bus until the write is done.
   - A DMAC write commits in its last data cycle.
   - Result: burst 46.00 and cycle steal 50.00 Icyc per unit, every size **[HW S11 46.26-46.46; S10 50.0-50.6]**.
   - `v1_dmac_int.cpp` now checks both rates. The new `make v1-dmac-int-bugs` (`V1_DMAC_BUG_24`, plus the
     `pair_wr_after_tail`, `pair_no_hold` and `dma_commit_at_writ` sed mutants) catches every one.
8. **`tb/v1_bsc_stub.sv` (WI-0b).**
   - Write beats land at capture.
   - A write of another line is allowed from a line read's critical beat.
   - Read overlap one Bcyc after it.
   - Stub mutants 17-19.
   - Its memory write is off during a power-on reset: random initial values, seed 5, wrote garbage.
   - `v1_bsc_stub_tb.sv` / `v1_bsc_agree_tb.sv` scenarios follow.

**Mutant suites after this session:** v1-cache 68 / 68 caught, v1-bsc 57 / 57, v1-dmac-bugs PASS, v1-dmac-int-bugs PASS.

## 5. Check policies for the real memory (documented in the checkers and SOC.md)

- **caches-sq `check.py --m3`.** This is "kern.S bodies exact where integral":
  - a T row's cycle count and every event count per unit are exact (±0.03) where the console's per-unit value is
    integral;
  - otherwise the total is within ±2 Icyc, the window's two Bclk-phase edges;
  - c/u is derived, not compared;
  - `--self --m3` catches every total moved out of the band.
- **soc-design `check.py`.**
  - `f:TOL` token mode: ci4's P2 / miss loops, `TOL` = 2 × 24 / 256.
  - `--refresh-slack 0.1875`: a loop period printed with a fraction is accepted within it. A minimum or maximum of
    five runs on the real memory may carry one refresh collision more or less than the console's, because the
    refresh timer runs free of the program. Brackets and counts stay exact. See SOC.md 9.27.
- **core-integration `mkexpected.py`.** ci4's expected values are M3's to add:
  - the `ram_*` rows are class `fpu` and exact;
  - the `p2_*` / `miss_*` rows are class `cache` with `f:0.1875`.
  - The regenerated ci / ci2 / ci3 entries are unchanged.
- **soc-design `mkexpected.py`.** The c1 B rows the graft keeps warm, and ipra16's B − A, are now `open`:
  - `b1_ill`, `b4_ill`, `b1_fpe`, `b2_fpe`, `b6_dae`, `b3_trap`, `b4_trap`;
  - their 27-36 on the console came from dcload's printf between repetitions.
  - `b3_ill` stays `cache`: the probe's own code evicts it in the console layout too.
- **exceptions-intc `check.py`.** A `stub` line equal to the console's is accepted, because a grafted run starts from
  KOS's state.
